## 2. この企画にした理由（狙い）

ユーザーが集めた参考動画の中で、反応が大きかったのは「世界の危険な場所」（1.5万いいね）だった。それを受けて作った「G20の危険レベル」の動画（外務省のデータ）を見て、ユーザーが次の2点を挙げた。

1. **ギャップがいい**：「G20（主要な先進国・新興国）なのに、危険な国がある」
2. **「特定のこの場所」が「へー、そうなんだ」を生む**：国全体ではなく、どの地域が、なぜ危ないか

ここから、シリーズの核を次の一言にした。

> **有名な観光地・名物のすぐ隣に、外務省の危険地帯がある。**

狙いは、視聴者に「えー、そうなんだ！マジで！？」と思わせること。同時に、国全体が危険という誤解は避けて、**地域ごとに違う**という正確さを保つ（ここが「煽るだけの動画」との違いで、信頼にもなる）。

最初の案（イスタンブールの人気 vs トルコの危険地域）は、場所が遠くて「なぜイスタンブール？」になった。そこで、**危険地域に近い観光地・名物**に絞り直した。この教訓がシリーズの選び方の基準になっている（7章）。

シリーズ名は「危険と隣り合わせの観光地帯」。「地帯」は、外務省の「国境地帯」「危険地帯」と言葉が揃い、「隣り合わせ」の対比が強く出る（「観光地域」のほうが少し自然な日本語だが、印象が弱い）。

## 3. 動画の型（全編の構成と、各パートの狙い）

1080×1920、60秒以上（実際は約90〜110秒）。声は VOICEVOX の冥鳴ひまり（落ち着いた低めの声。動画内と概要欄に「VOICEVOX:冥鳴ひまり」を必ず入れる）。

| # | パート | 内容 | 狙い |
|---|---|---|---|
| 1 | フック①（約3秒） | 「危険と、隣り合わせの、観光地帯。**◯◯編。**」 | シリーズ名と国名を、毎回同じ言い回しで。**固定の枠を覚えてもらう**（シリーズとして認識される） |
| 2 | フック②（約4秒） | 「危険と、隣り合わせの、観光地帯を、知っていますか？」 | 視聴者への問いかけ。「知らない」→続きを見る |
| 3 | フック③（約4秒） | 「今日は、◯◯に存在する、危険と隣り合わせの、観光地帯を、紹介します。」 | これから何が起こるか（紹介）を言って、離脱を防ぐ |
| 4 | **魅力の紹介**（3場面、各5〜6秒） | 世界遺産・名物などを、**写真と登録年つき**で。右上に、国のどこにあるかの小さな地図 | まず**行きたくなる気持ち**を作る。ここが「落差」の土台。背景の写真は国ごとに違うので、**国が変わると違う動画に見える**（フックの背景も最初の場面の写真） |
| 5 | **ターン**（約5秒） | 「でも、この地域は、外務省が出している、危険地帯と、隣り合わせなんです。」→ 背景と音が、**落ち着いた配色から赤黒の恐怖演出に切り替わる** | 動画のいちばんの山。ギャップを、画面と音で体感させる |
| 6 | **危険地域の地図** | 国の地図に、レベル4・3・2の地域を、レベルの高い順に出す。人気の場所の印も出し、色が変わる（レベルが明かされる） | 「特定のこの場所」の「へー」。画面が揺れ、赤くフラッシュする（レベル3以上が明かされる瞬間に1回だけ。点滅の繰り返しはしない） |
| 7 | 人気の場所のレベル／距離 | その場所が、どのレベルの地域にあるか。必要なら「◯◯から、レベル3の地域まで、約◯キロ」 | 誤解を防ぐ（**人気の場所が危険情報の対象かどうかを、必ず明示する**）。距離は概算と明記 |
| 8 | 注意点（任意） | 外務省が伝えている注意を、公式の文言に沿って | 事実に基づいて、緊張感を保つ |
| 9 | 結び | 「◯◯が怖いかどうかは、場所によって違います。行く前に、外務省の最新の情報を確認してください。」 | 煽って終わらせない。**誠実さ**を残す（信頼の土台） |
| 10 | CTA（約11秒） | 「世界の意外な、旅行リスクを、地図と、公的情報で、解説しています。次の地域も、紹介します。フォローしてね。気になる国は、コメントで教えてください。」 | **フォローする理由**（何が得られるか）を言う。コメントで次の国の希望を集める |

### 各演出の意図

- **落ち着いた配色 → 赤黒への切り替え**：魅力の場面では、写真と淡い青の背景。ターンで赤黒・筆文字・血の滴り・火の粉・心音に変える。落差が大きいほど、「でも」が効く。
- **筆文字風のフォント**（Kaisei Tokumin、Yuji Boku。どちらも OFL で商用可）：恐怖感。
- **コードで描く地図**：国の形は Natural Earth（パブリックドメイン）。権利の問題がなく、地域の位置も正確に出せる。実写の写真は、出典と権利を確認できるものだけ（5章）。
- **場所の印の色の変化**：最初は白。その場所の説明に入ると、地域のレベルの色に変わる（視聴者が「この場所は？」と予想→答え合わせの流れ）。
- **地図は、必要なら拡大する**（`map.bbox`）。トルコは南東部だけ、カンボジアは北部だけを拡大して、場所の関係が見えるようにする。
- **「国境から30km以内」のような距離で決まる地域は、国境線のデータから自動で描く**。手で描くと不正確になるのと、「観光地が範囲内か」を座標から検証できるため。

## 4. 表現のルール（守ること）

- **検証できていない内容を載せない**。数字・場所・登録年などは、出典を記録して、2系統で照合する（5章）。
- 「危険な国」と言い切らない。**「外務省の危険情報が出ている地域がある」**と言う。国全体ではなく、その国の中の一部の地域のレベル。画面にも「地域ごとに違います」と明記する。
- 順位づけはしない（「危険な国ランキング」にしない）。同じレベルの国は同順になり、根拠として弱い。
- 差別・決めつけに見える表現を避ける。政治的な争点が強い国・地域（イスラエル・パレスチナ・ウクライナ・ロシアなど）は、当面扱わない。紛争が実際に起きている場合（カンボジア・タイ国境）は、**外務省の文言をそのまま**使い、評価や非難をしない。
- 危険レベルは頻繁に変わる。画面に「（◯年◯月◯日時点）」と「危険情報の最終更新」を出す。投稿直前に取り直す。
- 外務省の名前を使う場合は、公式アカウントと誤認されないように、概要欄に「外務省 海外安全情報オープンデータ（加工して作成）」の出典を書く。

## 5. データと検証（どこから何を取り、どう確かめるか）

| 使うもの | 出典 | 確認した条件 | 検証の方法 |
|---|---|---|---|
| 危険レベル・地域・注意点 | 外務省 海外安全情報オープンデータと、各国の危険情報ページ | 商用可。出典を書き、加工した旨を書く | 国別XMLのレベルを、公式ページ本文と照合。画面の地域の文言は、公式ページの「危険レベル（または危険度）」の節にそのまま出てきて、直後のレベルが一致すること。注意点は、本文にそのまま出ること。**1つでも外れると止まる** |
| 世界遺産・登録年 | Wikidata（CC0）と ja.wikipedia | 事実のみ使う | Wikidata の指定と登録年 × ja.wikipedia の本文に、年と「世界遺産」が出ること。両方一致したものだけ |
| 食文化など（Wikidata に項目が無いもの） | ja / en の Wikipedia | 事実のみ使う | ja と en の2記事の本文で確認。**同じ Wikipedia の別言語版で、独立した2系統とは言えない**ので、報告に残す |
| 観光地の座標 | Wikidata（CC0） | | 国境線データと合わせて、距離を計算 |
| 国の形・国境線 | Natural Earth 50m（パブリックドメイン） | 国境線は目安 | 「国境から30km以内」は、国境線から描き、観光地が範囲内と主張するときは、計算上も範囲内であることを確かめる（5km単位の概算） |
| 写真 | Wikimedia Commons | **CC0・パブリックドメイン・CC BY だけ**使う（CC BY-SA・NC・ND は使わない） | API でライセンスと作者を確認し、画面と概要欄に表示 |
| 声 | VOICEVOX 冥鳴ひまり | 商用可、クレジット必須 | 画面下と概要欄に「VOICEVOX:冥鳴ひまり」 |

- **UNESCO の公式サイトは、ボット対策で自動取得できない**ので、回避せず、使っていない（Wikidata と Wikipedia で代用）。
- Wikimedia の API は共有IPで回数制限（429）が出やすい。1回失敗したらブラウザ（ヘッドレス Chromium）経由に切り替え、写真は標準サイズのサムネイルで取る。取得結果は `build/` に保存し、2回目以降はネットワーク不要。
- 結果は、国ごとに `build/<id>/fetch_report.txt` に残る。

### 魅力の紹介の書き方（ジョージア編で固まった方針）
- **危険地帯に近い場所を選ぶ。** 近さは座標から計算し、数字にできるものは数字で見せる（ズグディディ→レベル3の地域まで約5km）。
- **「世界遺産に登録された」だけで終わらせない。** 絵が浮かぶ、具体的な事実を1〜2個入れる（山の高さ・最高峰、ナポレオンのデスマスク、スターリンの生まれた町と古代の洞窟都市）。
- **事実は、ja / en の Wikipedia の本文に出てくるものだけ。** ja 版に項目が無いときは、en のみとし、画面に明記する。
- 1場面は約6.5〜7秒、ナレーションは2〜3文。長くなるぶん、全体は約140秒になる（短くするなら、注意点か結びを削る）。
- 読者の反応: 「面白くなった」（ジョージア編）。他の編（トルコ〜タイ）も、この書き方で見直す余地がある。

## 8. TikTok の運用（仮説。10本の結果で見直す）

### ハッシュタグ
ユーザーの実績：別アカウントで「#つば九郎」「#NPB」「#畜ペン」を付けて、フォロワー1,800まで伸びた。小さくて濃いファン層の固有名詞のタグが効いた、と考えている（1アカウントの話なので、タグだけの効果とは言い切れない）。

このシリーズでは、同じ3層で組む。
1. **シリーズ名のタグ（固定）**：`#危険と隣り合わせの観光地帯`（過去作がまとまる「棚」）
2. **濃い層のタグ（国・場所ごと）**：国名、場所名、世界遺産名（例：`#トルコ` `#ギョベクリテペ` `#プレアヴィヒア寺院`）。固有名詞は、ファンが検索する
3. **大きな枠のタグ**：`#世界遺産` `#海外旅行` `#外務省` `#危険情報`
3〜5個程度。無関係なタグは効果が出にくい。キャプションの冒頭に、国名・地名のキーワードを置く（検索に効く、という説明が多い。TikTok 公式の確認は未了）。

濃い層のタグを知る方法：TikTok の検索バーに、場所・名物・世界遺産・外務省・雑学などの語を打って、サジェストと、フォロワーの少ないアカウントで伸びている動画のタグを控える。タグのページの閲覧数（数十万〜数百万あたりが狙い目、というのは私の経験則）。**これはユーザーの画面での確認が要る**（スクリーンショットを送ってもらえれば、こちらで集計する）。

### 投稿文（`post.md` に自動生成）
- タイトル：「【◯年◯月◯日時点】危険と隣り合わせの観光地帯 ◯◯編。…」
- 概要欄：内容の要約、「危険情報は国全体ではなく地域ごとに違います」「渡航前に外務省の最新の情報を確認してください」、出典（外務省・写真の作者とライセンス・地図・音声）
- 固定コメント：「次に見たい国は、どこですか？コメントで教えてください！」

### フォローされる理由
CTAで、「世界の意外な旅行リスクを、地図と公的情報で解説」「次の地域も紹介します」を言う。プロフィールにも、同じ趣旨を書く。

### 評価（10本のまとまりで）
- 見る指標：最後まで見られた割合、保存数、コメント（母数が少なくても読める指標）。再生数は、新規アカウントだとぶれる。
- 比べるもの：国ごとの違い（知名度・距離の影響）、タグの組み合わせ、フックの言い回し。
- フォロワーの属性は、フォロワーが増えてから確認する。
- TikTok のクリエイターリワードの条件（1分以上の動画、フォロワー1万・直近30日の視聴10万など）は、変わりうる。公式ヘルプで確認する。

## 9. 英語など他言語の展開について（判断：日本語の10本を終えてから）

- 外務省の情報が、海外でどのくらい信頼されているかは、データが見つからなかった。英語圏では、米国・英国の渡航情報が中心で、日本の外務省の情報は、日本人向けという位置づけだと思う（推測）。
- 英語にするなら、**日本・米国・英国の渡航情報を並べる比較**が強い（レベルの違い自体が「へー」）。米国・英国の情報の再利用条件は、使う前に調べる。
- 追加の作業：英語の合成音声（商用の条件の確認）、翻訳、誤訳の確認、日米のレベルの意味の違いの説明。
- 英語化に備えて、文言をテーマの YAML に集めた作りを保つ（コードに国ごとの文言を書かない）。

## 10. 新しい国を足す手順

1. `data/series_candidates.csv` と `python3 src/candidates.py` で、国を選ぶ。
2. 外務省のページ（`build/mofa_cache.json` の `section`）で、危険地域の文言とレベルを確認する。国境からの距離で決まる地域は `border:` で描ける。
3. 観光地・名物を決める。世界遺産は Wikidata、座標（P625）で国境からの距離を計算する。
4. 写真を探す（Commons。CC0・パブリックドメイン・CC BY だけ。検索は `incategory:"CC-BY-4.0"` などで絞ると速い）。
5. `themes/<country>_place_risk.yaml` を、既存のもの（トルコ・カンボジア）を元に書く。台本は他の言い回しに合わせる。
6. `python3 src/run.py themes/<id>.yaml` で、検証 → 地図 → 音声 → 映像 → 投稿文まで通す。検証で止まったら、文言か名前を直す。
7. 静止画で、文字のはみ出し・重なりを確認する（地図の `map.bbox`、`label_at` の位置、`side` の向き）。
8. `build/<id>/final.mp4` と `post.md` を、投稿に使う。

## 11. 未解決・要確認

- **JNTO「日本人訪問者数ランキング」**：ダウンロードに、利用申請フォーム（利用目的・公開の有無・発行元種別）が要る。ユーザーの申請待ち。受け取ったら、候補表の「人気」を置き換えて、順位を出し直す。出典は元データ＋「JNTOが作成」の明記が条件。
- **ガジアンテプの食文化**の根拠が弱い（Wikipedia のみ）。UNESCO の公式ページでの確認を、投稿前に。
- 候補表の「隣り合わせ度」と「観光地・名物」は暫定。国ごとに作る前に検証する。
- 濃いハッシュタグの候補（TikTok での確認がユーザー側に必要）。
- TikTok の再生リスト機能の条件（連続視聴させるため）。
- 声・フォント・演出の強さの好み（ユーザーの感想待ち）。
- 英語展開の判断（10本の結果が出てから）。
