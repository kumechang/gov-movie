## 1. 目的

日本の政府オープンデータ／API から「ゴシップ的に面白いランキング」を作り、TikTok のショート動画としてシリーズ化する。狙いは **TikTok クリエイターリワードプログラムの再生数収益**（いわゆる再生数稼ぎ）。

### ターゲット（検索して見そうな人）
1. 35歳・パート主婦
2. 32歳・営業職サラリーマン
3. 35歳・建築職人

### 動画の型（ユーザーが持ってきたサンプル7本を分析した結果）
- 上部に固定タイトル、**カウントダウン形式のランキング**（下位→1位）
- 画面下に公的な出典表記
- 最後は「あなたの県は何位？」のコメント誘導
- 「決めつけないで」など炎上防止の一言
- 他アカウントでは転職アプリ等のPR導線で収益化している例もあった

## 2. 現状（できたこと）

サンプルとして **「都道府県別 離婚率ランキング（2024年）」** の完成動画を作った（約91秒、1080×1920、30fps、H.264＋AAC）。

- 映像: 日本地図を都道府県ごとに色分けし、47位→1位まで順に発表。冒頭フック、TOP10の区切り、東京都の紹介、コメント誘導まで入っている。
- 音声: VOICEVOX（四国めたん、速さ1.28）による自動ナレーション＋効果音（ティック音、ドン、和音）。映像の時間割はナレーションの長さに合わせて自動で組まれる。
- ユーザーの反応: 映像のクオリティは「びっくりした」「すごい」と高評価。ナレーション付き版も好評。
- **未確認**: ナレーションの実際の聞こえ方（読み間違い・音量）は、作成側では聴けていない。ユーザーの感想待ち。

## 4. 技術構成

### 4.1 パイプライン

```
データ(common.py) → 地図マスク(geo.py → geo.pkl)
                  → ナレーション生成(narration.py → narr/*.wav, narration.json)
                  → 時間割(common.py がnarration.jsonの長さから計算)
                  → 効果音+音声合成(audio.py → audio.wav)
                  → 映像描画+書き出し(render.py)
```

- 映像: Pillow で1フレームずつ描画 → 生のRGBを ffmpeg にパイプ（libx264, yuv420p, crf 19）。
- 音声: numpy で効果音を合成し、ナレーションを重ねる。仕上げに ffmpeg の `loudnorm`（I=-16）で音量を揃えた。
- 地図: Natural Earth 10m admin_1（パブリックドメイン）の GeoJSON を手動で投影。沖縄は左下にインセット表示。

### 4.2 ファイル（`src/`）

| ファイル | 役割 |
|---|---|
| `common.py` | データ（47都道府県の値）、順位（同率対応）、色の区分、**読み上げ文**、**動画の時間割**。映像・音声が共通で読む |
| `geo.py` | 都道府県ごとのマスク画像を作り `geo.pkl` に保存。入力は `ne_admin1.geojson` |
| `narration.py` | `common.narration_lines()` の各文を VOICEVOX で音声化し `narration.json` に長さを書き出す |
| `audio.py` | 効果音の合成＋ナレーション配置 → `audio.wav` |
| `render.py` | フレーム描画と書き出し。`python3 render.py still 1.0,4.5` で静止画確認、`python3 render.py out.mp4 audio.wav` で動画書き出し |
| `narration.json` | 前回生成した読み上げ文・長さ・読み（kana）の記録 |

### 4.3 実行順

```
cd src
python3 geo.py                              # 初回のみ（ne_admin1.geojson が必要）
python3 narration.py                        # ※VOICEVOX環境のpythonで実行
python3 common.py                           # 時間割の確認（合計秒数など）
python3 audio.py
python3 render.py out.mp4 audio.wav
ffmpeg -i out.mp4 -c:v copy -af loudnorm=I=-16:TP=-1.5:LRA=11 -c:a aac -b:a 160k final.mp4
```

## 5. セットアップ（Mac想定。作成時はLinuxのクラウド環境だった）

### 5.1 必要なもの
- Python 3、`pillow`、`numpy`、`ffmpeg`（libx264付き）
- 日本語フォント: `render.py` の13行目 `FP = '/usr/share/fonts/opentype/noto/NotoSansCJK-%s.ttc'` は **Linuxのパス**。Macでは Noto Sans CJK JP を入れるかパスを書き換える。ウェイト指定（Bold/Black等）の使い方は `render.py` の `F(size, weight)` を見る。
- 地図データ: `https://raw.githubusercontent.com/nvkelso/natural-earth-vector/master/geojson/ne_10m_admin_1_states_provinces.geojson` を `src/ne_admin1.geojson` として保存（約40MB。ダウンロード可能なことは確認済み）。`geo.py` は `iso_a2 == 'JP'` で絞り、`name_ja` で都道府県名を引く。

### 5.2 VOICEVOX Core
- 公式: https://github.com/VOICEVOX/voicevox_core （※ `voicevox_engine` ではなくこちらを使った。Pythonから直接呼べるため）
- 使用バージョン: **voicevox_core 0.17.0**（Python wheel）、ONNX Runtime は `voicevox_onnxruntime 1.23.2`、音声モデルは `0.vvm`、辞書は `open_jtalk_dic_utf_8-1.11`
- 作成時の環境では GitHub API が使えず、リリースのアセットを個別にダウンロードした。普通のMacなら公式READMEの `download` コマンドで一式を取得できるはず。PyPI の `voicevox-core` は空のプレースホルダーなので **pip install voicevox-core は使えない**。
- `narration.py` は `VV = '../tts/vv'` 配下に `ort/`, `dic/`, `0.vvm` がある前提。Macでは onnxruntime のファイル名が違う（`.dylib`）ので、`narration.py` の `glob` を直す。
- 話者: スタイルID 2 = 四国めたん（ノーマル）、3 = ずんだもん（ノーマル）、8 = 春日部つむぎ。`narration.py` の `STYLE` と `SPEED` で変更。
- **クレジット表記が必須**: 動画内（`render.py` のフッターに「音声：VOICEVOX:四国めたん」を入れてある）＋TikTok概要欄。話者を変えたら表記も変える。

## 6. データ検証ルール

- サンプルの出典: 厚生労働省「人口動態統計」2024年（国立社会保障・人口問題研究所「人口統計資料集2026」表12-32）。離婚率＝人口千対、全国平均 1.55。
- 検証方法: 同じ表を2回独立に読み取って一致を確認、さらにユーザーが持ってきた別動画の表示値20件以上と照合して一致。
- 注意が必要だった点: ある記事が「東京=0.96（2025年概数）」と書いていたが、2024年表と整合しないため **採用しなかった**。年次・概数／確定数の混在に注意。
- 今後の新テーマでも、**出典URL・年・単位・読み取り方法を記録**し、可能なら2系統で照合する。数字を動画に載せる前に、最大値・最小値・全国平均が妥当かをコードで確認する（`python3 common.py` が最大/最小比などを出力する）。
- 画面とナレーションには「出典：〇〇（年）」を必ず入れる。

### 政府データの候補（ユーザーが調べた商用利用可の一覧から）
e-Stat、EDINET、法人番号、GビズINFO、法令API、不動産情報ライブラリ、官公需、海外安全情報。**商用利用の可否と出典表記ルールは、各サービスの利用規約を使う前に確認すること**（TikTokの再生数収益は商用に当たる）。

## 7. 既知の課題・TODO

### 7.1 すぐやること
1. ナレーションの聞こえ方を確認（読み間違い、「1.13」「1.55」の読み方、間の長さ、音量）。`narration.json` の `kana` に読み仮名が入っているので、そこで確認できる。直すときは `common.narration_lines()` の文を言い換える（例: 「1.55」が「ごーごー」と読まれたため、東京の文から数字を外した）。
2. ユーザーの「細かいところで気になること」を聞く（映像側の細かい修正。ユーザーは後回しでよいと言っている）。
3. 声・速さの好みを決めてもらう（四国めたん／ずんだもん／男性声など）。

### 7.2 量産に向けた設計変更（最重要）
現状の `common.py` は離婚率に直書き。**テーマを差し替えるだけで動画ができる形にする。**
- 入力を1ファイル（YAML/CSV/JSON）にまとめる: テーマ名、年、単位、出典名、出典URL、47都道府県の値、色の区分のしきい値、全国平均、読み上げ文のテンプレ、注意書き（「決めつけないで」等）。
- `render.py` の固定文字（タイトル、「離婚率」「1位の約半分」「東京都は20位」など）を入力から読むようにする。いまは離婚率前提の文言が残っている。
- 都道府県データなら地図テンプレがそのまま使える。**市区町村・業種・企業・商品などのランキング用に、地図なしのテンプレ**（棒グラフ／カード形式）も用意する。
- 1テーマ=1コマンドで「データ取得→検証→動画書き出し」まで走る形にする。

### 7.3 データ取得の自動化
- e-Stat API は appId が必要（ユーザーに発行を頼む必要あり。無料）。それ以外の API でキー不要のものはキー不要で取る。
- 作成時のクラウド環境はネットワークが許可リスト制で、e-Stat等に届かなかった。**ユーザーのMac上のClaude Codeなら届く可能性が高い**ので、まず接続確認する。

### 7.4 運用面
- **TikTokへの投稿はユーザーがやる**（自動投稿はアカウント停止リスクがあるため推奨しない）。投稿用のタイトル、概要欄（出典・VOICEVOXクレジット・ハッシュタグ）、固定コメント案は動画と一緒に自動生成するとよい。
- 動画の「独自性」: 同じ型の量産はオリジナリティ評価で不利になりうる。テーマごとに冒頭フック、色、切り口を変える工夫を入れる。
- 検索経由の再生が評価されやすいので、ペルソナが検索しそうなタイトル語（「離婚率 都道府県 ランキング」など）を動画内テキストと概要欄に入れる。
- 差別・決めつけに見える表現（地域・属性への蔑視）は避ける。サンプルでは「離婚の背景は人それぞれ。決めつけないでね」を入れた。
- 画面に使う地図・音声・データの権利表記を、概要欄にもまとめる（Natural Earthはパブリックドメイン、VOICEVOXはクレジット必須、データは出典明記）。

## 9. 付録: 作成時の注意点・ハマりどころ

- `python3 -I` を付けるとローカルの `common.py` を読めない。自作スクリプトは付けずに実行する。
- Pillow の `polygon` は座標が2点未満だとエラーになる（`geo.py` の `dp()` で回避済み）。
- 色は tuple で渡す（numpy配列のままだとエラー）。
- 映像のはじめに音が小さい問題は、`loudnorm` を最後に掛けて解決した（平均 -30.7dB → -22.3dB）。
- ナレーションを入れると初版で97秒になった。読み上げ文を短くし速さを 1.28 にして約91秒に収めている。
- 時間割は `narration.json` の長さに依存する。**読み上げ文を変えたら必ず `narration.py` → `audio.py` → `render.py` の順にやり直す。**
